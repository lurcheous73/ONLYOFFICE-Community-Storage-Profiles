# v0.3.2 — S3Compatible backend compatibility

Status: **test branch / do not migrate until acceptance passes**

Branch: `v0.3.2-backend-compatibility`

## Why v0.3.2 exists

Runtime testing against MEGA S4 with the AWS SDK shipped in ONLYOFFICE Workspace 12.8 found two backend assumptions that are acceptable to Amazon S3 but are not sufficiently portable for a generic S3-compatible consumer:

1. `TransferUtilityUploadRequest` / `UploadPartRequest` use the AWS SDK's default checksum/trailer behaviour. MEGA S4 rejected the stock request with `SignatureDoesNotMatch` / `Trailer signature verification failed`. The same installed SDK passed when `DisableDefaultChecksumValidation = true` while normal SigV4 payload signing remained enabled.
2. stock `S3Storage.MakePath()` formats tenant/module/domain/path and then performs only one `Replace("//", "/")`. When more than one adjacent component is empty, a consecutive slash can survive. MEGA S4 rejected that object key. Migration has a real empty-domain copy path, so this is not only a synthetic test case.

The upstream baseline used by this patch is ONLYOFFICE CommunityServer `v12.8`, commit `fe1fa7babd093969e939ba6ff45a9fee1299dc93`.

## Architecture

v0.3.2 deliberately **does not replace or modify `ASC.Data.Storage.dll`**.

At install time it:

- downloads the exact upstream `S3Storage.cs` source from the pinned CommunityServer commit;
- generates a separate `ASC.Data.Storage.S3Compatible.S3CompatibleStorage` implementation;
- compiles it as `ASC.Data.Storage.S3Compatible.dll` against the assemblies already installed in Workspace;
- deploys that new assembly beside each installed `ASC.Data.Storage.dll`;
- changes **only** the `S3Compatible` consumer's `handlerType` to the new assembly;
- adds the hidden `disabledefaultchecksumvalidation=true` compatibility property to the `S3Compatible` consumer;
- restarts Community Server so the new handler can be loaded.

The legacy `S3` consumer continues to use:

`ASC.Data.Storage.S3.S3Storage, ASC.Data.Storage`

The first-class `S3Compatible` consumer becomes:

`ASC.Data.Storage.S3Compatible.S3CompatibleStorage, ASC.Data.Storage.S3Compatible`

## Compatibility changes

The new handler makes two targeted changes relative to the upstream S3 implementation:

- repeatedly collapses `//` in generated object keys until no consecutive slash remains;
- applies `DisableDefaultChecksumValidation` to both `TransferUtilityUploadRequest` paths and to synchronous/asynchronous `UploadPartRequest` paths.

It does **not** disable SigV4 payload signing.

Because `BaseStorage` keeps some state and quota helpers internal to `ASC.Data.Storage.dll`, the separate handler mirrors the required state and synchronizes the stock base fields after `Configure()`. Quota calls are implemented in the custom handler using the public quota-controller interface. This avoids modifying or IL-patching the stock assembly.

## Safety model

`storage-profiles-v0.3.2.sh install`:

- is version-gated to `onlyoffice/communityserver:12.8.0.1971`;
- requires the existing v0.3 `S3Compatible` consumer;
- refuses a pre-existing custom handler assembly;
- backs up every consumer config it changes;
- records SHA-256 for every stock `ASC.Data.Storage.dll` before installation;
- verifies those stock hashes are unchanged after deployment;
- creates a rollback manifest;
- does **not** read stored provider credentials;
- does **not** call `settings/storage`, `updateStorage`, or the migration service.

If installation fails after the transaction begins, the script restores its config/file changes and restarts Community Server.

## Install on the test portal

```bash
cd /opt/onlyoffice-community-storage-profiles

git fetch origin \
  refs/heads/v0.3.2-backend-compatibility:refs/remotes/origin/v0.3.2-backend-compatibility

git merge --ff-only origin/v0.3.2-backend-compatibility

bash scripts/storage-profiles-v0.3.2.sh install
bash scripts/storage-profiles-v0.3.2.sh status
```

Do **not** press CONNECT after installation.

## Non-migrating acceptance test

The acceptance test defaults to `/root/.mega-s4-test.env` and uses the dedicated disposable bucket already configured there. It never calls an ONLYOFFICE storage-settings or migration API.

```bash
bash scripts/test-s3compatible-v0.3.2.sh
```

The test covers:

- migration-shaped `tenant/module//path` normalization;
- small `Save()` through `TransferUtility`;
- read-back and SHA-256 verification;
- `SavePrivate()` through the second `TransferUtility` path;
- multipart initiate;
- three `UploadChunk()` parts (5 MiB + 5 MiB + 1 MiB);
- multipart complete;
- read-back and SHA-256 verification;
- delete and gone checks;
- cleanup on failure.

Only after the complete acceptance test passes should a fresh migration attempt be considered.

## Rollback

```bash
bash scripts/storage-profiles-v0.3.2.sh rollback
```

Rollback restores the pre-v0.3.2 `S3Compatible` consumer config, removes the separate custom assembly, restarts Community Server, and verifies the stock `ASC.Data.Storage.dll` hashes remain unchanged.
